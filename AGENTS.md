# LKUser Development Notes

`lkuser` is an overlay repository that builds a user-space environment on top of:
- LK (`lk/` submodule) for the kernel and base build system
- newlib (`newlib/` submodule) as the user-space libc

Treat `lk/` and `newlib/` as upstream submodules unless intentional submodule changes are required. `lk/` follows LK's branch `lkuser` (the `branch` in `.gitmodules`), where the kernel changes the executive needs land first, and LK's master merges the branch from time to time; a commit there is never rewritten, since lkuser pins it. `build-*` and `install-*` directories are generated output — never treat as source or commit files from them.

## Quick Commands

Run from repository root:

```bash
make -j $(nproc)     # build everything: newlib (first time), LK kernel, user apps/libs
make test            # build + generate FAT image + boot QEMU (exit QEMU with Ctrl-A X)
make test-auto       # build + boot QEMU non-interactively, run the test apps, pass/fail (riscv64, riscv32, arm64)
make test-auto-all   # make test-auto for every profile in turn
make clean           # clean kernel + user-space outputs (keeps newlib)
make spotless        # also remove newlib build/install trees
make fs              # just regenerate build-$(ARCH)/root.fat
make list-toolchain  # print the required cross toolchain prefix
make size-table     # the executive's code per file at LK_DEBUG=0 and 2, against its budgets (scripts/size-table.sh; any ARCH and PROFILE)
```

Architecture is selected with `ARCH` (default `riscv64` in the top-level `makefile`). `riscv32` is riscv64's executive, user space and tests at 32 bits (rv32imac/ilp32 apps on LK's sv32 supervisor kernel); `arm64` is the same again on LK's `qemu-virt-arm64-test` (aarch64 apps at EL0, 4KB pages); all three build and pass the gate. The trap stubs (`lib/lku/syscalls.c`) and the kernel's syscall entry exist for riscv, both widths, and arm64. `arch/arm`, `lib/lku/crt0_arm.S` and `sys/project/qemu-arm-usertest.mk` are left as they were and do not build. Never assume host architecture — always check/propagate `ARCH` on build and test targets. `ARCH` is lkuser's name, not LK's: LK's projects set their own (`riscv` at either width, `arm64`), so the makefile keeps a command line `ARCH` out of LK's make, and `arch/<arch>/arch.mk` sets `ARCH_FAMILY` for the sources shared by a family (`lib/lku/crt0_$(ARCH_FAMILY).S`). The toolchain prefix comes from `arch/<arch>/arch.mk`: `riscv64-elf-` for riscv64, and for riscv32's user space too, through its rv32imac/ilp32 multilib, and `aarch64-elf-` for arm64 (overridable via `TOOLCHAIN_PREFIX`; CI fetches prebuilt toolchains from newos.org/toolchains, and installs QEMU and mtools from the distro, and for riscv32 the distro's `opensbi`, whose rv32 `fw_dynamic.bin` it links in as the `opensbi-riscv32-generic-fw_dynamic.bin` Ubuntu's QEMU lacks); LK picks its own, so the riscv32 kernel builds with `riscv32-elf-` (arm64's with `aarch64-elf-`, the same as its user space). Building the FAT image requires mtools (`mformat`/`mcopy`); `make test` requires `qemu-system-riscv64` (`qemu-system-riscv32` for riscv32, `qemu-system-aarch64` for arm64, run as `-machine virt -cpu cortex-a76`).

The kernel's profile is selected with `PROFILE` (default `usertest`, any target: `make test-auto PROFILE=consoled`). It names the LK project `sys/project/qemu-$(ARCH)-$(PROFILE).mk`, built into `build-qemu-$(ARCH)-$(PROFILE)`; the apps and the image are the same for every profile (direct carries the image in its kernel), and `make clean` cleans the selected one. A profile's knobs live in one file, `sys/project/profile/<profile>.mk`, which every `qemu-<arch>-<profile>` project includes after setting `LKUSER_LK_PROJECT` to the LK project underneath (`project/qemu-virt-riscv64-supervisor-test.mk`, `project/qemu-virt-riscv32-supervisor-test.mk`, `project/qemu-virt-arm64-test.mk`). `usertest` compiles in every kernel service, and starts `/init/bin/init` at boot, which runs the apps the kernel command line names (the shell stays, for loading them by hand). `consoled` is usertest with the console served from user space by `/init/bin/consoled`, started at boot ahead of init, which is born connected to it and hands that connection down: every app runs against it unchanged, which is the proof that a client cannot tell a kernel service from a user one. `mini` is the small end: only the console and process services, a 16-slot handle table, and one static process started at boot (`/init/bin/minitest`), with no file system once it is loaded and no apps for the console to load. `direct` is the end with no shell and no console commands: LK's shell-less target underneath (`project/target/qemu-virt-riscv.mk`, with `SUBARCH` and `RISCV_MODE` set in the project file, or `project/target/qemu-virt-arm64.mk`), with `lib/fs`, rofs and its embed module and the usertest services. Its image is the same files as an rofs image: the makefile builds `build-$(ARCH)/root.rofs` from `FS_LIST` with `lk/scripts/mkrofs.py`, each file at a page boundary (`ROFS_ALIGN`), before the kernel, and passes its path as `ROFS_EMBED_IMAGE`, which links it into the kernel as the memory block device `rofs0`; the kernel mounts it at `/init` and starts its one boot process, `/init/bin/init`, which makes the rest. Every profile but mini keeps the boot image mounted read-only at `/init`, beside a memfs at `/tmp` where processes write; with the `lkuser root` prefix left at `/`, those two are all user space sees. A profile is the project's make knobs, which `sys/lib/lkuser/rules.mk` reads: `LKUSER_SERVICES` (the kernel services compiled in), `LKUSER_BOOT_FS` on `LKUSER_BOOT_DEV` (the boot image, by default `fat` on `virtio0`), `LKUSER_BOOT_UNMOUNT` (1: unmounted once the boot processes are loaded, and no `/tmp`), `LKUSER_BOOT` (processes started at boot, `path[:arg...][@service]` each, the path in the kernel's tree) and `LKUSER_HANDLES` (the slots of a handle table, default 64).

`make test` is an interactive QEMU boot. `make test-auto` is the gate for the selected profile (`scripts/qemu-test.sh`, riscv64, riscv32 and arm64); a change to the executive, `lib/lku` or the harness runs `make test-auto-all` with each of `ARCH=riscv64`, `ARCH=riscv32` and `ARCH=arm64`, since usertest alone does not see a consoled or mini regression, nor one arch another. CI (`.github/workflows/github-ci.yml`) runs it too, on every push and pull request: each arch with gcc 15.2.0 and 11.3.0, `make test-auto-all` at `TEST_SMP=1` and `4` with `TEST_TIMEOUT=180`, on the runner's distro QEMU, and keeps the console logs of a failing job as an artifact. Each run boots with stdin closed, no NIC (`-nic none`: arm64 virt's default one needs an iPXE ROM a minimal QEMU install lacks) and a scratch copy of the image (`build-$(ARCH)/test-auto.fat`) attached, which the kernel mounts read-only at `/init`; the direct profile attaches no disk. With `TEST_INIT=1` (the harness's `-i`, the default in every profile but mini, whose boot process is its test) there is no autorun: the apps go to init on the kernel command line as `lkuser.init`, each without its `=code`, or as a list in the image (a `TEST_APPS` entry `@<name>`: init reads `/init/etc/<name>`, and the harness, given the image's source directory with `-d`, reads the same file to check each app in it as if it had been an argument; refused without `-i`), and `lkuser.halt` has the kernel power off once the boot processes are gone, after its halt-time object dump, before the shell would start. Otherwise an `lk.autorun` script runs each app in `TEST_APPS` with `lkuser load`/`run`, waits for the ones run in the background and the profile's boot processes (`lkuser wait`) and powers off. `TEST_APPS` and `TEST_BOOT` (the boot processes to check, `name[=code]` each, given to the harness as `-b`) default per profile; a boot process is checked like an app but not loaded, and has to end by itself after the apps. It passes only if:
- QEMU powered off by itself within `TEST_TIMEOUT` seconds (default 60; a run takes a few seconds),
- no kernel panic or assert was logged,
- with `-i`, the halt-time dump lists only kernel endpoints and the closed endpoints of user servers,
- the image is as it was (its sha256), since nothing may write to it,
- every app's process logged `lkuser: process <pid> (<name>) exited with code N` with the code its entry expects, and an app expected to exit 0 printed the exact line `<NAME>: PASS` (name upper-cased). Exits are counted per name, so processes an app spawns under other names (spawntest's `child`) do not count.

Each `TEST_APPS` entry is `name[:arg...][&][=code]`: `rawtest:a:b:c` runs `lkuser load /init/bin/rawtest a b c` and expects code 0, `faulttest=-40` expects -40, and `echoserver&` runs with `lkuser start` while the entries after it run, so it has to end by itself (the autorun's `lkuser wait` waits for it before powering off). The makefile quotes each entry for the shell. The usertest default is `TEST_LIST_usertest`, `rawtest:a:b:c calltest boottest posixtest spawntest faulttest=-40 ipctest regtest echoserver& echotest consoletest`, which the makefile writes one per line to `build-$(ARCH)/etc/usertest.list` (rewritten only when the value changes) and puts in the image as `etc/usertest.list`: with `-i` usertest's `TEST_APPS` is `@usertest.list`, without it the entries themselves, and an explicit `TEST_APPS` works either way; its `TEST_BOOT` is `init` with `-i` and empty without (init then has nothing to run, and its lines can tear against the shell's starting up); consoled's is the same with `consoletest:quit` last and `TEST_BOOT='consoled init'` (`consoled` without `-i`); mini has no apps (the autorun only waits and powers off) and `TEST_BOOT=minitest`; direct runs usertest's `TEST_APPS` (`@usertest.list`, from the image linked into its kernel), `TEST_BOOT=init`; consoled's stay on the command line, so every `test-auto-all` runs both ways in. boottest and posixtest run on newlib, the others without libc. `rawtest` covers user entry, the startup block and its handles, the trap ABI, `debug_write`'s checks on bad user pointers, unserved syscall numbers and exit. `calltest` covers handles and rights, endpoints, every transport check of `call`, handles carried by requests (moved and lent) and replies (taken back when a call fails), a 64KB echo, the vm, time and process services, files, directories and path handling through the namespace and file services, every kind of write to the image at `/init` refused (read-only FAT answers `ERR_NOT_ALLOWED`, rofs `ERR_NOT_SUPPORTED`; in direct, which has no disk to checksum, this is the check that the image holds), and memory objects (mappings, their rights and lifetime, `file.READ_INTO`/`WRITE_FROM`, and a read-only `lk_call_args` proving `reply_len` is written before the service runs). `boottest` covers stdio, floating point, heap growth across vm chunks and sbrk; its PASS line comes from an exit handler. `posixtest` covers stdio and POSIX file calls, directories and errno through lib/lku. `spawntest` spawns `/init/bin/child` (`apps/child`, a mode per `argv[1]`) with arguments and a memory object and reads its exit code through a process handle, checks that a child is born with only the handles handed to it (none, one, six and `LK_MSG_MAX_HANDLES`, counted by the child) and that a dup handed down keeps the rights it was made with, takes every way out of a process with one thread or several (exit, `thread_exit`, a fault, a kill), kills children blocked in `time.SLEEP`, in `console.READ` (the closed stdin never answers it) and in `wait`, checks the rights on process and thread handles and the spawns the service refuses, and runs a thread of its own. `faulttest` stores to an unmapped address. `regtest` checks the registers a thread owns: the main thread and every new one are born with the thread pointer (`tp`, `tpidr_el0`) and every FP register zero, and eight threads, with eight more in a copy of itself run as `regchild` (argv[0], so the harness does not count it), each keep values of their own in the thread pointer and the callee-saved FP registers (`fs0`-`fs11`, `d8`-`d15`) across a spin of three quanta, `time.SLEEP` and `console.WINSIZE`, and in a caller-saved one (`ft0`, `d16`) across a spin with no call in it; riscv32 (rv32imac) has the thread pointer only. `ipctest` covers user endpoints with its own threads as servers and clients and `/init/bin/child` as a client killed mid-call, a server exiting mid-call and a client connecting from another process: `recv`, `msg_read`/`msg_write`/`reply` and their range checks, stale and forged tokens, timeouts (and a server keeping its call's place on the endpoint until it next uses a token whose caller left), faults on either side, an endpoint closing under queued callers and a blocked receiver, handles carried both ways (moved, lent and taken back at the reply, in transit while queued, refused by a full table), impulses before calls and the pool running dry, `CONNECT_NOTIFY` (refuse, accept, cookies, peer handles, `connection_signal` seen by a multi-item `wait`), `CONN_CLOSED` and `PROCESS_EXITED`, groups and `max_active`, namespace mounts, and each IPC row with a handle lacking its right. `echoserver` (run with `&`) mounts two endpoints, one `max_active` 1, at `/srv/echo` and `/srv/echo1` in one group served by two threads, speaks the kernel echo service's protocol (`sys/svc/echo.h`) plus the test ops of `apps/include/echotest.h`, and ends on `ECHOTEST_QUIT`, failing if two calls on the single endpoint ever overlapped. `echotest` finds it with `namespace.LOOKUP` (retrying while the server starts), runs the same echo checks against it and the kernel echo service (64KB requests the server reads with `msg_read`), lends it a memory object, gets an impulse every tenth call, calls both endpoints from several threads at once, sees its `CONN_CLOSED` counted, and tells it to quit. `consoletest` checks the console protocol the same way whichever side serves it (the kernel console in usertest, consoled in consoled): a write in three pieces, several threads writing at once while a child waits in `console.READ`, the refusals (an unknown op, bad payloads, a lent handle on every op) and READ and WINSIZE clipped to the reply's room; with `quit` it reads consoled's counts (`CONSOLETEST_STATS`, `apps/include/consoletest.h`), tells it to quit and sees the console die (`PEER_CLOSED`, then `ERR_CHANNEL_CLOSED`), so its PASS line goes out through `debug_write`. `consoled` serves the console protocol relaying to the kernel console through its own handle, with one thread for every call; a READ waits by its token while a second thread reads a line from the kernel console for it, only while a READ waits, so writes go on meanwhile; a READ whose caller left is swept before the next receive. It prints its counts and `CONSOLED: PASS` at `CONSOLETEST_QUIT`. `minitest` (mini's boot process, no libc and no heap, its thread's stack in `.bss`) checks that it was born with exactly the console and process connections, that its handle table holds `argv[1]` slots (the project passes `LKUSER_HANDLES`), the IPC rows between two of its threads, and that `SPAWN` finds nothing to load. `init` (every profile's boot process but mini's, no libc) spawns `/init/bin/<name>` for each of its arguments `name[:arg...][&]`, with the arguments after the name and a dup of every handle it was born with under the same tag, runs each to its end before the next one starts unless it ends in `&`, waits for every one and prints `INIT: PASS`; one it cannot spawn prints an `INIT: FAIL` line and makes it exit 1. An argument `@<path>` is a list: a file it reads through the namespace a line at a time, each line an app in `TEST_APPS`' syntax cut at its first `=` (blank lines and `#` lines skipped), so the number of apps in the foreground has no bound (those in the background stay at 16, as do arguments: the command line holds 15 and 256 bytes); a list it cannot read is an `INIT: FAIL` line and exit 1 too, and one inside a list is refused. It prints through `debug_write`, so it never calls the console it hands down. `TEST_SMP` sets `-smp`. The console log is kept in `build-$(ARCH)/test-auto.log` (`test-auto-<profile>.log` for the other profiles), the scratch image beside it.

A user fault ends its process. lkuser prints `lkuser: process <pid> (<name>) faulted: cause C, epc E, tval T` (riscv's scause, sepc and stval; on arm64 `faulted: esr E, elr P, far A`), then the registers the trap frame holds, each line starting `lkuser:   ` (riscv `ra`, `sp`, `gp`, `tp`, `s0`, `status`, `a0`-`a7`, `t0`-`t6`; arm64 `x0`-`x29`, `lr`, the user `sp` and `spsr`), and a line naming the thread, whether it is the process's main thread, and the main stack's range (`proc::main_stack`, 64KB), so an `sp` outside it shows; the harness matches none of these. The process exits with `ERR_FAULT` (-40); its other threads end too. Typing at `console.READ` is checked by hand, since the gate's stdin is closed: in `make test` (and `make test PROFILE=consoled`, where consoled relays it), `lkuser load /init/bin/hello`, `lkuser run`, and type a line. The direct profile has no shell, so its kernel is run with the app on the command line and no disk: `qemu-system-riscv64 -machine virt -cpu rv64 -bios default -m 512 -nographic -kernel build-qemu-riscv64-direct/lk.elf -append 'lkuser.init=hello lkuser.halt'` (the other arches' QEMU as for `make test`), and the line typed there goes to hello.

Local make overrides can go in an untracked `local.mk` (auto-included).

## Architecture: Two Build Systems, One Makefile

The top-level `makefile` drives three mostly independent builds:

1. **newlib** — configured/built once per arch into `build-newlib-$(ARCH)` and installed into `install-newlib-$(ARCH)` (stamp-file gated; only rebuilt after `make spotless` or `make clean-newlib`). riscv32 uses riscv64's (`arch/riscv32/arch.mk` points there), whose multilibs include rv32imac/ilp32; arm64 builds its own, `aarch64-elf`'s single lp64 libc. Configured with `--disable-newlib-supplied-syscalls`; its system calls come from this repo's `lib/lku`.
2. **LK kernel** — via `makefile.lk` (symlink to `lk/makefile`) with `PROJECT=qemu-$(ARCH)-$(PROFILE)`. `lk_inc.mk` sets `LKINC := sys`, so LK's module system also searches `sys/`: the project files live in `sys/project/`, and the kernel-side module is `sys/lib/lkuser` (referenced as module `lib/lkuser` in LK's namespace — note repo-root `lib/` is a *different*, user-space directory). Output: `build-qemu-$(ARCH)-$(PROFILE)/lk.elf`.
3. **User space** — the top-level makefile itself compiles apps and libs with its own simple rule system (not LK's): it `find`s every `apps/*/app.mk` and `lib/*/lib.mk`, which set `APP_SRCS`/`LIB_SRCS` etc. and include the shared `make/app.mk` / `make/lib.mk`. Those bind each app's `APP_CFLAGS`/`APP_INCLUDES`/... (and each lib's `LIB_*`) to its own objects, since the recipes run after the variables are cleared. Output goes to `build-$(ARCH)/`; the generated `.d` files are included, so header changes rebuild their users. Apps link with `ld`: the objects, then `--start-group` `APP_LIBS` (`lib/lku/lku.a`), newlib's `libc.a`/`libm.a` `--end-group`, then libgcc; crt0 comes out of `lku.a`, pulled in by the `_start` entry symbol. Per-arch flags, linker scripts, and newlib multilib paths are in `arch/<arch>/arch.mk`.

To add a user app: create `apps/<name>/app.mk` modeled on `apps/boottest/app.mk` (newlib) or `apps/calltest/app.mk` (no libc; `apps/include/lktest.h` has the string, output and `CHECK` helpers, `test_spawn`, which hands a child dups of the caller's service connections beside handles of its own, and through `testpaths.h` the two paths a test uses: `TEST_IMAGE`, `/init`, for files in the image, and `TEST_TMP`, `/tmp`, for those it writes) — it is discovered automatically. Kernel-side code follows normal LK module conventions (`rules.mk`, `MODULE_DEPS`, ...). `lk/scripts/check-module-deps.py` does not cover `sys/lib/lkuser`: with the default `--root` it never reads the module's sources, and with `--root .` it names LK's modules `lk/lib/...` and reports every one as missing. Check a new `#include` against `rules.mk` by hand.

## The Kernel Side (`sys/lib/lkuser/`)

Kernel objects share `object` (`object.h`): an `lk::ref_counted` count, a kind (endpoint, connection, group, memobj, process, thread), the number of handles naming the object and a signals word with the threads waiting on it, no virtual functions. Every object is made by `object::make<T>` and stays on a registry list (what `lkuser objs` walks) until its last release, which calls `object::destroy`; that unregisters it and deletes the concrete type by kind. Derived types are reached with `static_cast` after a kind check (each has a `kKind`), never `containerof`. The last handle to an object going runs its kind's last-handle action: an endpoint or a group closes. A connection also counts its client views (every handle without the internal `kRightPeerView` marker, which `connection_accept` sets on the server's peer handle and `handle_dup` and transfers keep): the last one going sends a user endpoint `CONN_CLOSED`. A connection to a kernel endpoint with a release hook hands its cookie to that hook when the connection object is destroyed, not at its last handle, so a call in progress keeps the service's state for it alive.

- `proc.cpp`: a process owns an LK user aspace, its handle table, its threads, the memory objects mapped into it (a list, each mapping holding a reference), its exit status, and its IPC state: the inflight slots of the calls it has received (16, `LKUSER_INFLIGHT`) and the pool `impulse_send` takes from (32, `LKUSER_IMPULSE_POOL`). `proc::create` builds the startup block from argv and its startup handles: for a process the kernel makes itself (a boot process, or one the console loads) a connection to every registered kernel service with a tag, then the handles passed in; a process `process.SPAWN` makes is born with exactly the handles its spawner moved in, and nothing else. `start` maps and zeroes a 64KB main stack, copies the block to its top and starts the main thread; `start_thread` starts another (refused once the process has exited). `exit` (first call wins) kills every thread of the process, prints `lkuser: process <pid> (<name>) exited with code N` (the gate matches the name and the code, so the code stays last on the line), ends every call the process has received with `ERR_CHANNEL_CLOSED` (`cancel_inflight`) and closes every handle. A reaper thread (started from an `LK_INIT_HOOK`) joins the threads of exited processes, frees their address spaces and drops their mappings, then raises the process's `LK_SIGNAL_TERMINATED` and, if its spawner asked, sends `PROCESS_EXITED` over the connection held for that; an exited thread's LK thread and kernel stack stay until then. The `proc` itself lives on, a zombie with its pid and exit code, while a handle names it.
- `thread.cpp`: a user thread embeds its LK `thread_t`, the `pending_call` of its call in progress and the wait queue it blocks on in `wait`, sets `TLS_ENTRY_LKUSER` to itself and enters user space with `arch_enter_uspace`, unless it was killed before it ran. Its kernel stack is at least 8KB, whatever the arch's default (one page on arm64): `SPAWN` reads an image through the file system and block drivers on it. Every way a thread ends (exit, `thread_exit`, a fault, a kill) goes through `thread::exit_current`, which raises its `LK_SIGNAL_TERMINATED`; the last thread out of a process that has not exited ends it with code 0. It must outlive the LK thread, so it is dropped only after the reaper joins it.
- `memobj.cpp`: a memory object, v1: one physically contiguous run of zeroed pages (at most `LK_VM_MEMOBJ_MAX`, 16MB), which the kernel reaches through the physmap and `vm.MEMOBJ_MAP` maps with `vmm_alloc_physical`. Its pages go back to the pmm when no handle and no mapping remains.
- `wait.cpp`: the `wait` row: up to `LK_WAIT_MAX_ITEMS` (8) objects, each with a mask; the thread links a `wait_edge` onto each and blocks interruptibly on its own queue until a signal in an item's mask rises (`object::update_signals` wakes the matching edges) or the timeout passes, and reports the first item showing one. Signals: `TERMINATED` (processes, threads), `READABLE` (an endpoint with a call or impulse queued), `READABLE`/`WRITABLE`/`ERROR` on a connection (server-set) and `PEER_CLOSED` (its endpoint closed).
- `handle.cpp`: the per-process handle table (`LKUSER_HANDLES` slots, 64 unless the profile sets it; handle h is slot h - 1, so 0 is never a handle, and the lowest free slot goes first), `handle_close` and the attenuating `handle_dup`. A full table refuses with `ERR_NO_RESOURCES` rather than growing. Rights are checked before kind: a call on an endpoint handle is `ERR_ACCESS_DENIED`, and a kind mismatch with the rights present is `ERR_BAD_HANDLE`.
- `endpoint.cpp`: endpoints (a user endpoint's queue of calls, its impulses, its receivers, its group and its connections), connections, `connect` (a handshake with `CONNECT_NOTIFY`), `connection_set_cookie`/`connection_signal`, and `call`, which checks a request the same way for either kind of endpoint: a kernel endpoint's handler runs on the caller's thread in the caller's aspace, sees the handles the request carries and may give the caller handles with the reply (see Messages and services); a user endpoint's call goes to `ipc.cpp`. An endpoint's last handle closing ends its queued calls and wakes its receivers with `ERR_CHANNEL_CLOSED`, drops its impulses and raises `PEER_CLOSED` on its connections; calls already received can still be replied to.
- `ipc.cpp`: calls to user endpoints (see User endpoints): the caller's `pending_call` queued, `recv` into an inflight slot, `msg_read`/`msg_write`/`reply`, `connection_accept`/`connection_refuse`, and every way a call ends.
- `impulse.cpp`: `impulse_send` and the queueing of impulses, the per-process pool's and the kernel's (`CONN_CLOSED` embedded in each connection, `PROCESS_EXITED` in each process, so they never fail for want of an entry); each queued impulse holds a reference to its holder.
- `group.cpp`: groups: `recv` on a group takes an impulse from any member first, then a call from a member below its `max_active`; members sit on one of three lists (impulses, calls, idle) kept by `endpoint::changed_locked`.
- `msg.cpp`: `msg_buffer`, one side of a call as the caller's iovecs (at most `LK_IOV_MAX`, checked against the aspace when loaded), read or written at any offset through `copy.cpp`.
- `copy.cpp`: every access to user memory. A kernel-mode fault on a user address is fatal, so pages are looked up with `arch_mmu_query` under `vmm_aspace_lock` and copied through the physmap, returning `ERR_FAULT` for anything outside the aspace, unmapped, or lacking USER plus READ/WRITE. It works on any aspace, active or not. Syscall handlers receive user pointers as `user_ptr<T>`, which has no dereference. The pmm hands out pages as their last user left them, so every mapping given to user space (image pages, the main stack, `vm.ALLOC`) is cleared with `zero_user_pages` first.
- `boot.cpp`: the boot processes (`LKUSER_BOOT`), from an init hook at `LK_INIT_LEVEL_APPS - 1`, after the services register and the block devices appear, before the shell. It mounts the boot device read-only at `/init` and a memfs at `/tmp`, makes and loads every entry (one that fails is reported and left out), each with the words of the kernel command line's `lkuser.<name>` (`name` its file name, the words separated by `+` or spaces) after the arguments the entry gives it, points each `@service` at the user endpoint its process is born with (`serve_service`), unmounts `/init` if `LKUSER_BOOT_UNMOUNT` says so, and only then starts them all and puts them on the list `lkuser wait` waits for. The service table is thus written while no process runs. The hook does all this on a thread of its own with a user thread's 8KB kernel stack, which it joins, since loading through the file system and block drivers runs deeper than the hooks' stack allows on arm64. The reaper tells it as each boot process is freed (`boot_reaped`). With `lkuser.halt` on the command line the boot processes are the whole run: the hook waits for the last to be freed, so the init levels after it, the shell's among them, never run, then empties the `lkuser wait` list, prints every object left between the lines `lkuser: halt: objects` and `lkuser: halt: end` (the leak check, which should list only the service endpoints and the closed endpoints of user servers that have gone) and powers off with `platform_halt`.
- `svc/`: the kernel-resident services, one file each (`console`, `process`, `time`, `vm`, `namespace`, `file`, and the `echo` test service), registered at boot by `LKUSER_SERVICE` or `register_service`. A boot process may serve one in the kernel's place (`LKUSER_BOOT`'s `path@service`): the table entry then names the endpoint the process is born with (under `LK_TAG_SERVE_ENDPOINT`), so every process the kernel makes after it connects there under the service's tag. The entry stays on that endpoint after its server exits: the service is then dead (`ERR_CHANNEL_CLOSED`), not back in the kernel. `LKUSER_SERVICES` in `rules.mk` picks the files compiled in (`namespace` needs `file`; `console` sets `CONSOLE_HAS_INPUT_BUFFER=1` for the whole build, as READ waits on LK's `console_input_cbuf`); `sys/project/profile/usertest.mk` adds `echo`. `process` spawns (`SPAWN`: path, argv, moved handles under tags, all the child is born with, one under `LK_PROCESS_SPAWN_TAG_EXIT_NOTIFY` kept by the kernel for `PROCESS_EXITED`, `flags` 0; returns a process handle with WAIT INFO KILL DUP TRANSFER), starts threads (`THREAD_CREATE`: entry and sp; returns a thread handle), kills (`KILL`; the process exits with `LK_PROCESS_KILLED`, `ERR_CANCELLED`) and reports (`INFO`, about the caller or a process handle). `vm` gains `MEMOBJ_CREATE` and `MEMOBJ_MAP` (MAP plus a right per protection), and `UNMAP` takes a memory object's mapping down too. `namespace` resolves paths over LK's `lib/fs`, and keeps a table of 8 mounts: `MOUNT` gives a path to a user endpoint (moved, CONNECT; held without counting as a handle, so it dies with the server's handles, and a dead mount makes room for the next), `LOOKUP` hands out a new connection to the longest mount covering a path and the rest of it, `UNMOUNT` takes a lent handle to the mounted endpoint; `file` has no startup tag (`kNoTag`): each open file or directory is a connection to it that `namespace.OPEN` makes (`svc/open_file.h`), whose cookie is the open-file record, freed with the connection by the endpoint's release hook, which closes the `lib/fs` handle. `file.READ_INTO`/`WRITE_FROM` move bytes between a file and a memory object.
- `user.cpp`: the ELF loader `load_image` (borrows the target aspace with `vmm_set_active_aspace` while `elf_load` writes the segments, and puts the caller's back, a user thread's own for `SPAWN`), `resolve_fs_path` (`user.h`), which puts the `lkuser root` prefix in front of a path, `normalize_user_path`, which normalizes a path a process sent so `..` stops at the root, `resolve_user_path`, which does both (`namespace` and `SPAWN`), and the `lkuser` console command.
- `syscalls.cpp`: the typed dispatcher, `exit`, `thread_exit` and `debug_write`, and per arch the syscall entry and the two hooks LK's trap code calls on the way back to user mode (the kill hook also on a thread's first entry, from `arch_enter_uspace`): one prints a fault and ends the process with `ERR_FAULT`, the other takes a killed thread out through `thread::exit_current`. On riscv they are `riscv_syscall_handler`, `riscv_user_exception` and `riscv_user_kill`; on arm64 `arm64_syscall` (aarch64 only, an aarch32 trap is LK's unhandled case), `arm64_user_exception` and `arm64_user_kill`. The syscall entry enables interrupts around the dispatch and disables them again before returning, as LK's kill check on the way back runs with them off.

Allocation failure is an error the caller sees, never a panic: every `lk::make_ref`, `object::make`, nothrow `new` and `malloc` is checked and unwinds with `ERR_NO_MEMORY`. Plain `new` (LK's panics) and asserts on allocation results are not used.

Invariants that are easy to break:
- No reference is dropped with a handle table's mutex, a spinlock or `THREAD_LOCK` held. The last release takes the registry mutex and frees memory, and the console holds the registry mutex while it takes a table's. `handle_table` moves a removed reference out and drops it after unlocking; so does `proc`'s mapping list.
- A process's handle table is emptied by `proc::exit`, not by its destructor, so a handle naming the process itself cannot keep it alive.
- Object signals and their waiters are under `LKUSER_IPC_LOCK`, which is LK's `THREAD_LOCK` (interrupts off, pointer work only).
- A call to a user endpoint ends however its `pending_call`'s state says under `LKUSER_IPC_LOCK`, never by what a wait returned, since a reply can race a timeout. A server thread touching the caller (its buffers, table or process) sets the call's `busy` first, and the caller does not leave the call until `busy` clears, so the caller's aspace, which the reaper frees once its threads are gone, outlives every copy; and anything the server needs after that is held by reference.
- A caller leaving a received call (timeout or kill) cuts the inflight slot's link to its `pending_call`, which the thread reuses for its next call; the token then fails with `ERR_NOT_FOUND`, and the slot (with its place in the endpoint's `max_active`) goes the next time the server uses it.
- A handle moving between tables goes into the new one before it leaves the old, and a moved handle in a queued call counts as a handle of its object until a server receives it or the call ends, so no last-handle action runs in transit. When the moving process is the receiving one, the slot a moved handle left may already hold the new handle; the move does not close it.
- Killing a process (`proc::exit`, from `exit`, a fault or `process.KILL`) never stops a thread from outside: it latches LK's kill signal (`thread_signal_kill`) on each, and each ends itself at a kill point: a wait that opted in with `WAIT_QUEUE_INTERRUPTIBLE` returns `ERR_INTERRUPTED` and unwinds, and every entry to user mode, a thread's first or a return from a syscall, a fault or an interrupt, hands a killed thread to the arch's kill hook (`riscv_user_kill`, `arm64_user_kill`). The kill points are `time.SLEEP`, `console.READ`, `wait`, a caller waiting for its reply or handshake, and `recv`; every other wait (a mutex, a FAT read) is bounded and finishes first, and a thread spinning in user mode ends at its next timer tick. A handler that gets `ERR_INTERRUPTED` returns it; `call` then writes no reply. A new unbounded wait on a user's behalf must be interruptible, or a kill can hang the reaper, which joins every thread with no timeout.

## Syscall Mechanism (the key cross-file flow)

The raw syscall table is a single X-macro list: `sys/lib/lkuser/include/sys/_syscalls.h`, 21 rows of `LK_SYSCALL_DEF(num, ret, name, args...)`, every one with a handler; a number past the table returns `ERR_NOT_SUPPORTED`. Shared definitions live beside it:
- `sys/lk_abi.h`: handle and token types, the handle rights, the startup block and its tags (`LK_TAG_SERVE_ENDPOINT` for the endpoint a boot process serves, `LK_TAG_USER_BASE` up for handles a spawner and its child agree on), the signals `wait` watches, and the width and argument-width rules.
- `sys/lk_msg.h`: the message header, the impulse and the kernel's impulse types, and the argument structures of the IPC rows.
- `sys/svc/*.h`: one protocol per service.
- `sys/_errors.h`: LK's status codes as `LK_ERR_DEF(name, value)` rows. `sys/lk_err.h` expands them to enumerators for user space, and the kernel `static_assert`s each row against `<lk/err.h>` in `syscalls.cpp`, so a code that drifts from LK fails the build. The kernel never includes `lk_err.h`, whose names collide with LK's macros.

These headers compile on both sides, so they use only `<stdint.h>`/`<stddef.h>` types.

Trap ABI: on riscv (both widths, `ecall`) number in `a7`, arguments in `a0`-`a5`, the result in `a0`; on arm64 (`svc #0`, the return address already past it) number in `x8`, arguments in `x0`-`x5`, the result in `x0`. The result is a single status (`NO_ERROR` or a negative `ERR_*`, never an errno). Arguments are register width by preference: handles, rights and counts 32-bit, lengths `size_t`, tokens and cookies `uintptr_t`. An inherently 64-bit value may take a register pair on 32-bit, but neither the stubs nor the dispatcher map one yet (the dispatcher asserts that each argument fits one register), so the first such row has to add that mapping; times travel in the argument structures. Interrupts are enabled while a handler runs, and the thread is marked as inside a syscall.

- **Kernel side**: `syscalls.h` declares one `sys_<name>` per row from the row itself, with each pointer argument turned into a `user_ptr<T>`; a handler defined with another signature fails to link. `syscalls.cpp` converts the registers to the declared argument types (integers keep their low bits) and dispatches by number.
- **User side**: `lib/lku/syscalls.c` expands each row into an `lk_<name>` stub, a naked function on riscv (`li a7, n; ecall; ret`) and top-level assembly in a section of its own on arm64 (`mov x8, #n; svc #0; ret`), as gcc has no naked functions there; `lib/lku/include/lk/ipc.h` declares them.

To add a syscall: add a row with the next number, then define its `sys_<name>` handler in the kernel (replacing the `ERR_NOT_SUPPORTED` stub if the row exists). Both sides recompile from the same header, so numbers and signatures can never skew.

## Messages and Services

A request and a reply each start with `struct lk_msg_hdr` (`op`, payload `len`, `nhandles`, and `status` in the reply) and are laid out by the caller as iovecs in `struct lk_call_args`. `call` returns the transport's status, and the service's verdict is the reply header's `status`, so a client can tell "the call failed" from "the service said no".

Before any service sees a request, the transport checks it and answers `ERR_INVALID_ARGS` for each of these:
- a header that doesn't fit, or a reply buffer that can't take one;
- more than `LK_IOV_MAX` iovecs on either side;
- an op at or above `LK_OP_KERNEL_BASE`;
- a header `len` or `nhandles` that disagrees with the call.

Other transport answers: `ERR_FAULT` for an iovec or handle array outside the aspace, and `ERR_BAD_HANDLE` or `ERR_ACCESS_DENIED` for the connection. A request carries at most `LK_MSG_MAX_HANDLES` handles, each looked up before the service runs: moved (the default, needs TRANSFER) or lent (`LK_HANDLE_LEND(i)` in `handle_flags`, needs no right). `ERR_INVALID_ARGS` for too many or a lend flag past the last, `ERR_BAD_HANDLE` for no such handle, `ERR_ACCESS_DENIED` for a move without TRANSFER, `ERR_INVALID_ARGS` for a handle moved and named again in the same request. After those checks and before the service runs, the transport writes the call's results once, `reply_len` and the `reply_handles` room (cleared to `LK_HANDLE_INVALID`), so `ERR_FAULT` for an unwritable one means the service never ran. Kernel endpoints ignore `timeout_ns`: their handlers run to completion, or to a kill.

A kernel service is a `kernel_handler_t` taking a `kcall`, registered with `LKUSER_SERVICE(name, tag, handler)` in its own `svc/<name>.cpp`:
- `args<T>()` reads a fixed-size request (`ERR_INVALID_ARGS` unless the payload is exactly a `T`), and `reply(t)` writes a fixed-size reply (`ERR_NOT_ENOUGH_BUFFER` unless it fits).
- `read`/`write` copy the payload at any offset, clipped at the end, for streams of any size.
- `reply_handle(obj, rights)` gives the caller a handle with the reply, up to `reply_handles_capacity()` (the caller's `reply_nhandles`, else `ERR_NOT_ENOUGH_BUFFER`). It goes into the caller's table at once, so a full table is the handler's `ERR_NO_RESOURCES` to report, and is closed again if the handler returns an error or the call fails: a refusal never carries handles. A handler checks the capacity before doing work it would have to undo.
- `nhandles()`, `handle(i)` and `handle_as<T>(i, need, &out)` (`ERR_ACCESS_DENIED`, then `ERR_BAD_HANDLE` for another kind) show the handles the request carries, a lent one's rights without DUP and TRANSFER. A moved handle stays in the caller's table while the handler runs and leaves it once the handler returns success, even if writing the reply then faults; a refusal moves nothing. So the handle count never drops to zero in transit: a handler that keeps a moved object (`SPAWN` installs it in the child) adds it elsewhere before the caller's goes. A handler never keeps a lent object beyond the call. An op that takes no handles refuses a request that carries some (`expect_handles(n)`, or a check in the dispatcher), so nothing is moved to a service that drops it.
- The handler returns the service status. The kernel then writes the reply header, with `len` being how far the handler wrote and `nhandles` how many handles it gave.
- A fault on the caller's buffers fails the whole call with `ERR_FAULT`, whatever the handler returned.
- A `kernel_release_t` hook, passed to `register_service`, gets the cookie of every connection to the endpoint as the connection is destroyed. It may run on any thread with no user aspace, so it touches kernel state only.

Every process the kernel makes itself (the boot processes and those the console loads) is born with one connection per compiled-in service that has a startup tag (or to the user endpoint serving it in the kernel's place), under that tag, with `CALL IMPULSE WAIT DUP TRANSFER`. A process `process.SPAWN` starts is born with exactly the handles its spawner moved in, under the request's tags: what it may reach is what its spawner held and chose to pass, a handle or a dup of one with rights masked by `handle_dup`, and since a dup is a second handle to the same connection, a service never sees the hand-down. To add a service:
1. Write its protocol in `sys/svc/<name>.h`. Payloads are wire structs, so they get size and offset asserts.
2. Pick a tag: `sys/lk_abi.h` for a real service, from `LK_TAG_TEST_BASE` up for a test one.
3. Add the handler file and its name to `LKUSER_SERVICES`.

### User endpoints

A user server makes an endpoint (`endpoint_create`: flags, `max_active`, cookie; RECV CONNECT WAIT DUP TRANSFER) and receives on it, or on a group of endpoints (`group_create`/`group_add`/`group_remove`, RECV on both), with `recv`. A call to it is the same `call` as to a kernel endpoint, with the same transport checks, but the caller's thread queues its `pending_call` on the endpoint and blocks, interruptibly, until a server ends it or `timeout_ns` has passed (never sooner by the ns clock, perhaps a ms or two later; the same holds for `recv` and `wait`):
- `recv` takes an impulse first (token 0, the datagram in `info.impulse`), else the oldest call of an endpoint below its `max_active`, into one of the receiving process's inflight slots (`ERR_NO_RESOURCES` when all are taken): it copies the start of the request (header included) into the receiver's buffers, puts the carried handles in its table (a full table is `ERR_NO_RESOURCES`, and the call goes back to the head of the queue) and reports the token, the op, both cookies, the sender, `req_len` and `reply_max`. Moved handles leave the caller at this point, never before; lent ones get the lender's rights minus DUP and TRANSFER and are taken back when the call ends.
- `msg_read`/`msg_write` copy between the server's buffers and the caller's, at offsets from the start of the request and the reply (the reply's first 16 bytes are the kernel's header: `ERR_INVALID_ARGS`); outside the request is `ERR_OUT_OF_RANGE`, past the caller's reply room `ERR_NOT_ENOUGH_BUFFER`.
- `reply` writes its iovecs' payload after the header and the kernel writes the header around the server's status (op, `len` the furthest byte written, `nhandles`); its handles (TRANSFER, at most the caller's room) move to the caller. A refused reply moves nothing and leaves the call to the server.
- A fault on the caller's buffers ends its call with `ERR_FAULT` and the token with it; one on the server's own is only the server's `ERR_FAULT`.
- Every later use of a token whose call has ended, or whose caller left, is `ERR_NOT_FOUND`. A token is the slot index in its low 8 bits and a per-process generation above, from 1.
- With `LK_EP_FLAG_CONNECT_NOTIFY`, `connect` is a call of op `LK_OP_CONNECT` with no request or reply, which the server ends with `connection_accept` (sets the cookie and gives the server a peer handle, SIGNAL DUP TRANSFER, for `connection_signal` and `connection_set_cookie`) or `connection_refuse` (the client's `connect` returns `ERR_NOT_ALLOWED`).
- `impulse_send` (IMPULSE) queues a 32-byte datagram of a type from `LK_IMPULSE_USER_BASE` on the connection's endpoint with the connection's cookie, from the sender's pool. The kernel sends `CONN_CLOSED` when a connection's last client handle goes, and `PROCESS_EXITED` over a connection a spawner passed under `LK_PROCESS_SPAWN_TAG_EXIT_NOTIFY`.

## User Space (`lib/lku`)

- `crt0_riscv.S`, `crt0_arm64.S`: `_start` (after setting `gp` on riscv) calls `_start_c` with `sp` (the startup block) as its argument; `_lk_thread_entry` is the entry of the threads `lk_thread_start` makes.
- `msg.c`: `lk_msg_callv` (one call described by payload iovecs, the handles it carries and room for reply handles, header filled in and stripped off, no timeout), `lk_msg_call` (the same with one contiguous payload and reply), `lk_wait_one`, and the service clients declared in `<lk/services.h>` (`lk_console_write`, `lk_vm_alloc`, `lk_vm_memobj_map`, `lk_process_spawn`, `lk_ns_open`, `lk_ns_lookup`, `lk_ns_mount`, `lk_file_read`, ...). Each returns the transport's status if the call failed, else the service's. A client that shows a handle to a service (`lk_process_kill`, `lk_vm_memobj_map`) lends it; `lk_process_spawn` and `lk_ns_mount` move theirs. A server uses the raw rows of `<lk/ipc.h>` (`lk_recv`, `lk_msg_read`, `lk_reply`, ...) directly. `lk_thread_start` runs `fn(arg)` on a thread of the caller's: `arch_enter_uspace` passes no argument, so it puts `{fn, arg}` in a 16-byte frame at the top of the new stack and starts the thread at `_lk_thread_entry` in crt0, which calls `fn` and then `lk_thread_exit`. No libc is used. A process has no thread-local storage yet, so newlib is not safe with threads: the tests that start threads run without it.
- `newlib.c`: `_start_c` for newlib programs (the startup handles, the fd table, argc/argv, libc init, `exit(main(argc, argv))`), `_exit`, the status-to-errno mapping, the heap and time. `_sbrk` hands out memory from 64KB `vm.ALLOC` chunks with a bump pointer: newlib's malloc takes a jump in the break for space another sbrk user took, as long as the break only moves up, so a chunk placed below the last is refused and the break never moves down; each chunk has a page beyond the request for the alignment correction malloc asks for right after a jump. `sleep`/`usleep` use `time.SLEEP`, `gettimeofday` counts from boot (no wall clock), and newlib does not declare `clock_gettime` or `nanosleep` for this target.
- `fd.c`: the fd table (32 fds; 0-2 share the console connection, which `close` leaves open) and the file calls: `open`/`read`/`write`/`lseek`/`fstat`/`isatty`/`stat`/`unlink`/`mkdir`/`rmdir`/`ftruncate`/`truncate` over the console, namespace and file services. File I/O is positional, so the offset lives here; `O_APPEND` writes use the file protocol's append flag. The working directory is always `/`.
- `dirent.c` and `include/sys/dirent.h`: `opendir`/`readdir`/`rewinddir`/`telldir`/`seekdir`/`closedir` over `file.READDIR`. newlib's own `<sys/dirent.h>` refuses to compile, so `lib/lku/include` comes before newlib's include directory in `GLOBAL_INCLUDES`.
- A program without libc (`apps/rawtest`, `apps/calltest`, `apps/regtest`, `apps/spawntest`, `apps/child`, `apps/faulttest`, `apps/ipctest`, `apps/echoserver`, `apps/echotest`, `apps/consoled`, `apps/consoletest`, `apps/minitest`, `apps/init`) defines its own `_start_c`, so `newlib.o` never links in. The default riscv64 linker script puts a no-libc program into one writable and executable segment (with an ld warning) when the compiler makes an 8-byte constant (`.srodata.cst8`) and the program has no other initialized data, so these tests avoid such constants. On arm64 no app gets such a segment: code loads `R E` and any data `RW`, at ld's default 64KB alignment, kept so that a 16KB or 64KB page kernel is not ruled out (none has been tried).

The startup block (`struct lk_proc_args` in `sys/lk_abi.h`): `nargs` and `nhandles`, then the argument offsets, then (tag, handle) pairs, then the strings; offsets count from the start of the block. `lk_proc_args_find(args, tag)` looks a handle up by its tag.

## Packaging and Running

Every app/lib registers itself in `FS_LIST` (`<build file>:<fs path>` pairs; apps land stripped at `bin/<name>`, extra data files can be added — see `apps/posixtest/app.mk`; the makefile adds `etc/usertest.list`). `make fs` assembles these into `build-$(ARCH)/root_dir/` and then a 64MB FAT image `build-$(ARCH)/root.fat`, which `make test` attaches to QEMU as a virtio-blk device; the direct profile's kernel carries the same files as `build-$(ARCH)/root.rofs` instead, built before it.

Inside the booted LK console, user binaries are driven with the `lkuser` command:

```
lkuser load /init/bin/rawtest a b c   # create a process: load the ELF, argv = the path and what follows
lkuser run                            # start it and wait for it to exit
lkuser start                          # start it and go on; lkuser wait waits for it
lkuser wait                           # until every process started with start, and every boot process, has exited
lkuser root <path>                    # set the fs root: paths given to load and every namespace path live under it
lkuser objs [-f]                      # every kernel object: kind, refs, handles, what it is
lkuser profile                        # the services and where each is served, the boot processes, table sizes, the syscall table
lkuser handles <pid> [-f]             # a process's handles and their rights
```

`-f` takes no locks, for when something is wedged holding one. Once every process has exited and `lkuser wait` has returned, `lkuser objs` should list only the kernel service endpoints (until then a boot process that has exited stays on the wait list, a zombie, `process ... pid 1 'init'`), and in a profile with a served service its user endpoint, closed once its server has gone. In such a profile `lkuser wait` also waits for the boot processes, so it returns only once the server has been told to quit.

If adding a new architecture: add `arch/<arch>/arch.mk` (toolchain, flags, newlib multilib paths, `ARCH_FAMILY`), a crt0 in `lib/lku/` (one per family), its trap stub in `lib/lku/syscalls.c`, the kernel's syscall entry, user-fault hook and kill hook for that arch in `sys/lib/lkuser/syscalls.cpp` (LK has to check the kill signal on every return to user mode and on a thread's first entry, `arch_enter_uspace`, and call the hook), a `qemu-<arch>-<profile>` project per profile in `sys/project/`, the size tool in `scripts/size-table.sh`, and a QEMU invocation in the top-level `test` target (and `scripts/qemu-test.sh` for the gate).
